1. Introdução ao Controle de Versões

O controle de versões é um sistema que registra as mudanças em um arquivo ou conjunto de arquivos ao longo do tempo, permitindo recuperar versões específicas mais tarde.

Git

É um sistema de controle de versão distribuído (DVCS) local. Cada desenvolvedor possui uma cópia completa do histórico do projeto em sua máquina.

GitHub

É uma plataforma de hospedagem de código-fonte e colaboração baseada na nuvem que utiliza o Git. Permite compartilhar repositórios e colaborar com outros desenvolvedores em todo o mundo.

2. Configuração Inicial

Antes de começar a criar commits, é fundamental configurar sua identidade global no Git. Isso identificará o autor das alterações.

# Configurar nome de usuário
git config --global user.name "Seu Nome"

# Configurar e-mail do usuário
git config --global user.email "seu.email@exemplo.com"

# Verificar as configurações ativas
git config --list

3. Ciclo de Vida de Arquivos Local

Os arquivos em um repositório Git passam por diferentes estados desde a criação até o salvamento permanente no histórico.

  • Untracked: Arquivo novo que o Git ainda não está rastreando.
  • Staged (Index): Arquivo preparado e marcado para ser incluído no próximo commit.
  • Committed: Alterações salvas com segurança no banco de dados local do Git.
  • Modified: Arquivo rastreado que foi alterado, mas ainda não foi para a área de staging.

Comandos Essenciais:

# Inicializar um repositório na pasta atual
git init

# Verificar o estado atual dos arquivos
git status

# Adicionar um arquivo específico para a área de preparação (Staging)
git add nome-do-arquivo.txt

# Adicionar todos os arquivos modificados e novos de uma vez
git add .

# Gravar as alterações permanentemente com uma mensagem explicativa
git commit -m "Mensagem clara e descritiva do commit"

4. Resolução de Problemas e Erros Comuns

⚠️ Erro: Permissão Negada (Permission Denied) ao rodar git init

Causa: Este erro ocorre frequentemente no Linux ao tentar inicializar um repositório em diretórios do sistema (como /var/www/html/), que pertencem ao usuário root por padrão.

Como Resolver Corretamente (Opções):

  • Opção 1 (Recomendada): Alterar o proprietário da pasta para o seu usuário do Linux para ter permissões completas de escrita. 
    sudo chown -R seu_usuario:seu_grupo /var/www/html/meu_projeto
  • Opção 2 (Mais Segura para Aprendizado): Criar o projeto diretamente na sua pasta pessoal (Home), onde seu usuário possui controle total (ex: /home/seu_usuario/projetos/).

Importante: Evite utilizar sudo git init! Se você criar o repositório como root, todos os arquivos internos de histórico do Git pertencerão ao root, gerando erros recorrentes de permissão negada nos comandos seguintes como git add ou git commit.

5. Trabalhando com Repositórios Remotos (GitHub)

Para salvar seu código na nuvem ou colaborar com equipes, conectamos o repositório local a um servidor remoto como o GitHub.

# Vincular seu repositório local a um repositório remoto no GitHub
git remote add origin https://github.com/usuario/nome-do-repositorio.git

# Enviar os commits locais para o servidor remoto (ramificação principal)
git push -u origin main

# Atualizar seu repositório local com as alterações do servidor remoto
git pull origin main

# Clonar um repositório existente do GitHub para sua máquina local
git clone https://github.com/usuario/nome-do-repositorio.git

6. Ramificações (Branching) e Integração

As branches permitem isolar o desenvolvimento de novas funcionalidades, correções ou experimentos sem afetar a linha principal de produção (geralmente chamada de main ou master).

# Listar todas as branches locais
git branch

# Criar uma nova ramificação
git branch nova-funcionalidade

# Mudar para a ramificação criada
git checkout nova-funcionalidade
# Alternativa moderna: git switch nova-funcionalidade

# Criar e mudar para a branch ao mesmo tempo
git checkout -b nova-funcionalidade

# Mesclar as alterações da branch atual com outra branch (ex: trazer para a main)
# Primeiro volte para a branch principal: git checkout main
# Depois execute a mesclagem:
git merge nova-funcionalidade

7. Tabela de Referência Rápida

Comando Descrição Prática
git init Cria um novo repositório Git local.
git status Mostra o estado atual dos arquivos (untracked, modified, staged).
git add <arquivo> Adiciona arquivos à área de preparação (Staging Area).
git commit -m "" Grava a foto do estado atual dos arquivos com uma mensagem explicativa.
git log Exibe o histórico detalhado dos commits realizados.
git remote add origin Conecta o repositório local ao repositório remoto na nuvem.
git push Envia as alterações locais para o servidor remoto.
git pull Baixa e mescla as alterações do servidor remoto no repositório local.
